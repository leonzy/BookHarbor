权限投影与来源重试

状态 ACTIVE · 2026-11-22 · booksvr

原始诉求与边界

降低主服务 CPU，避免 SQLite 写锁反复触发来源全量核对，保留增量、挂载保护和任务进度。

现场证据

106 个在线 CPU 样本中有 100 个位于 RefreshAccessRootBatch 的失效 SQL。生产库的文件计数选择权限组合主键，只匹配版本与组合，未按书 ID 缩小范围。最大组合约 47 万条。核对子进程遇写锁退出后，旧调度在下一轮启动另一轮全量。

方案及边界决策

权限失效计数使用现有按书 ID 索引，不改变权限和计数语义。来源任务保留增量路径和移动事件，只在明确需要基线时运行全量。基线失败限频重试；路径变更失败不会升级为全量，单独重试数据库外发队列。监控丢失和挂载恢复仍通过现有基线及身份保护处理。

影响范围与回滚

后端权限与来源同步，涉及 spec/书库.md。无界面影响，接口和状态字段沿用。上线前查看任务状态，使用现有升级检查，回滚可恢复原二进制。

验证

现网只读对照三次，同一文件计数从平均 417 毫秒降至 0.14 毫秒。Linux 隔离容器通过访问权限、来源同步、临时写锁重试策略和小文件核查回归，并以普通用户验证不可读目录保护。Go vet 和规格文档通过。Windows 全套测试存在文件系统平台差异，以 Linux 专项结果判断本次上线。
