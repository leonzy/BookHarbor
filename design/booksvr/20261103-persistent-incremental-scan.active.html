持久增量扫描与断点继续

创建日期：2026-11-03 · 模块：booksvr / app · 状态：ACTIVE · 来源：用户要求默认增量、停止继续、独立全量核对，并优先导入 Amazon book 20001-25000

原始诉求

当前手动扫描及全部导入每次重新遍历所有目录树，无法从停止位置恢复，新增目录看不到具体进度。元数据补全不得被中断。

目标与设计决策

  • 扫描目录任务、目录快照、当前文件游标及累计结果持久保存于用户库。默认检查已知目录状态，仅枚举变化或未知目录；新子目录递归加入队列。原路径的已完成记录按大小和时间核对，索引书籍保留 ID、人工字段保护和来源同步职责。
  • 停止后保留待处理任务和当前目录游标；继续时仅恢复未完成目录。目录在暂停期间变化则重读该目录，避免遗漏新增文件。服务重启后在未主动暂停时继续任务。没有历史目录快照时建立一次明确可见的基线；不把未知状态静默当作已扫描。
  • 全量核对独立入口，明确说明会重新枚举全部文件；检查并识别变化，不清空书库、不重新导入所有书。指定目录受现有导入目录和健康保护约束。
  • 优先单独处理 /books1/Amazon book 20001-25000，仅索引原文件并逐批导入。实测发现的扩展名截断文件先检查真实头部，只有确认 MOBI 容器才按 AZW3 接纳，保留源文件名。
  • 界面显示扫描类型、运行/暂停/完成/等待挂载、已检查目录、已检查文件、新登记、已有跳过、失败、待处理目录及当前路径；总量发现中不显示虚假百分比。默认按钮为增量扫描或继续，单独菜单提供全量核对确认。

实现细化

用户补充：扫描模式必须对任意配置目录通用，不硬编码 Amazon。请求通过 path 与 mode 指定范围和模式；Amazon 仅作为本次现场任务参数。前端提示使用通用示例 /books1/collection。

目标目录使用同一持久队列先行运行限速索引导入。跨进程扫描租约禁止双重执行；停止代号由运行者每秒检查，页面可停止先行任务，再由正式服务继续。扫描阶段和导入批次阶段、是否自动导入写入进度。文件系统事件持久保存，暂停和重启不丢失已收到的变化；候选处理成功才确认相应事件版本。无事件监控时原地覆盖内容不能仅由目录修改时间发现，需要明确的全量核对补偿，事件溢出显示需要全量补偿的提示，不静默将默认扫描变成全量；显式全量核对成功后确认相应缺口。

普通文件和压缩包以不同任务类型排队，全部普通目录/文件先处理，ZIP 成员仍在有界批次处入库并更新持久进度。显式全量核对保留兼容性失败复核，默认增量不重复全库失败核查。发布使用已测试二进制替换主服务，元数据补全服务和阅读服务不重启；临时 Amazon 执行者停止到持久游标后由正式队列继续，避免两个导入者重叠。

入库结果通过候选 ID 关联到具体目录任务，分别合并扫描与入库阶段的跳过和失败，不以时间范围猜测归属。ZIP 成员按所属归档判断任务范围；临时 Amazon 执行者已处理的记录在接管时显式纳入任务关联。

自动导入启动时仅恢复未完成任务和持久事件，不因进程重启重新枚举所有配置根目录；设置新增根目录时只为新增范围建立基线。事件缺口仅提示显式全量核对。正常停止释放租约，异常退出留下的租约在异步任务中等待到期后自动续跑，不把短暂租约等待记为永久失败。

实现边界

变更 scan、httpapi 导入调度、Go CLI 接线、导入页及中英文文案。沿用数据库写入序列和挂载健康保护，不把离线当成空目录或删除；扫描不负责删除书库记录。元数据补全独立服务不重启。更新 spec/书库.md；按 interface-review full 模式审查相对 origin/main 的全部本地变更，不提交无关 OPDS 工作。

真实界面审查发现确认弹窗的名称挂在内部容器，且程序化打开未提供原生触发器焦点恢复。改用 Vuetify activator 插槽，将名称放在 dialog 根节点，并关闭该弹窗过渡以保留减少动画偏好；增加 DOM 断言后重新测试与发布前端。

现场复核发现旧目录预检会创建写测试临时文件并枚举目录，导致每次手动扫描先改变目录 mtime，使未变化目录也被重新读取。扫描入口和后台导入改用浅层只读预检，仅打开目录并读取至多一个条目；设置页详细诊断保持原有行为。新增保留 mtime 的接口回归，再重新执行 Go 与现场增量验证。

窄屏和键盘复核确认原组件库仅用浅色覆盖层提示按钮焦点，新增扫描和确认控件补充 2px 主题前景色外框与 2px 间距；避免依赖低对比覆盖层。复测明暗色焦点与窄屏。

明亮主题测得默认辅助文字 rgba(0,0,0,.87) 再乘 .6 透明度，合成后约 4.29:1，低于普通文字 4.5:1；本控件标签和辅助文案改为完整继承主题前景色，不改变全局主题。主按钮白字与 #1976D2 为约 4.60:1。

重复 Linux 包测试捕获一项隔离夹具问题：ZIP 批次运行超过心跳周期时，普通 :memory: SQLite 新连接会得到空库。新目录队列测试限制内存夹具单连接，保留心跳并重跑整个扫描包；生产文件数据库不受该夹具限制影响。

最终主进程启动首试遇到与补全并行写入造成的短暂 SQLITE_BUSY，已回退旧二进制恢复服务，元数据进程未重启。发布控制器改为等待 Supervisor 有界重试和真实监听就绪，超过期限才回退，避免把首次短暂退避当作最终失败。
