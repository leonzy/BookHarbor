1. 原始需求

修好导入页统计和文案，重复归已跳过；分开显示实际书籍、成功处理文件、来源缺失。核实是否完成及慢因，测试通过部署、提交推送。追加截图反馈：页码输入、总页数、跳转按钮保持同一行，不再在组件内部换行。

2. 目标与边界

统计文件与书目分开，历史记录立即按新口径分类，不重新导入或改写状态；原文件、挂载保护和正在运行的自动监控保持安全。

3. 证据

线上 2026-10-21：续跑任务表为空，ready/queued/importing 为零，indexed 410140、exist 41935、drop 51500、failed 12416；最后成功时间 10-20 18:14:33。书目 380783、确认缺失 29618。自动监控正在再扫描已有目录，来源核对上轮106秒。扫描进度不是待导入量。批次统计缺少 import_id / scan_id 索引，逐行读状态、重复 COUNT 造成轮询额外负担。

4. Grill 与决策

  • 实际书籍按 books 主键统计，含来源缺失；可浏览数量另显示，避免让用户认为缺失已被删除。
  • 成功文件只含 imported/indexed；exist 和 drop 都是已跳过，失败独立；四类合计等于候选总数，expanded 容器排除。
  • 来源缺失按已确认不可用的书籍计数，不以当次 stat 失败推断，更不绕过挂载校验。
  • 聚合在 SQLite 中完成，批次索引启动时增量建立；不得每次请求执行 DDL 或扫描实体文件。
  • 全量手动任务完成与自动监控扫描区分文案；来源同步是独立后台状态。仍有失败不说全部书成功。

5. 实现

Summary 单次 GROUP BY 汇总文件分类，增加 library_books、available_books、missing_source_books。列表与轮询共享 Summary；批次 COUNT GROUP BY 通过覆盖索引。页面始终显示书目/文件/缺失解释，已处理标签明确按文件，重复原因可查。增加后端分组、历史记录过滤、共享书籍多文件、缺失、故障测试；前端多语言与页面测试。

6. 影响与回滚

影响 booksvr/internal/scan、httpapi、app/imports、三语言、spec/书库.md；API增加字段兼容旧字段。只增加索引，不迁移或删除业务数据。部署前在线一致备份，保留旧镜像，复制原容器配置及全部挂载，优雅停止后替换，失败回退。
