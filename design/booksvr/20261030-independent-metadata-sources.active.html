元数据来源独立限速与并发调度

2026-10-30 · booksvr · ACTIVE · 用户要求所有来源可同时检索，分别控制频率

原始诉求与目标

取消单本最多两个来源、全局30秒一轮的限制。各已启用且配置可用的元数据来源独立推进、独立限速、独立退避。保留人工编辑和版本校验，不中断导入及阅读。

方案与决策

新增按书籍和连接划分的持久任务队列，阶段为搜索、详情、封面、完成。每个来源至多一个在途请求，全局至多4个；请求间隔默认5秒，按来源连接可配置1至3600秒。每个调用都经过限速，不只限制搜索。间隔从请求结束后计算，并向上取整到秒；停用、忽略结果和正常退出同样保存冷却时钟，失败退避不缩短已配置的间隔。文件提取与网络协调器分别使用独立循环并共享单实例租约，协调器不等待网络，也不等待文件解析；后台关闭时不再接纳或应用网络结果。

每轮最多为每来源预填100本已有待联网书，新增文件处理通过小型入队表追加；联网队列以初始化上界区分新入库与历史书籍，优先服务新入库，使用连接、优先级、到期时间的索引寻址；使用队列与游标索引，不加载全库，不重置文件游标。成功的匹配按来源立即补缺；来源错误独立指数退避，最多3次；限流时保留并遵守上游 Retry-After（数字秒或 HTTP 日期，安全上限7天；未提供时至少等待5分钟），鉴权失败单独提示并延长等待。限速单位为插件的搜索、详情、封面能力调用；第三方插件内部的子请求继续受其客户端超时与主机并发保护。空结果结束该来源该书的本轮检索，不反复浪费额度。结果写入前重读现有书籍，并在事务内核对书名、作者和ISBN的预期快照，避免并发编辑或其他来源已改变版本后混填。

无书源的 Legado 暂不入队；没有接入能力的 Calibre 检索不重复占用网络。其余启用来源均参与。实测发现微信读书 GetCover 使用本地匿名结构别名而非协议类型，导致整个 MetadataProvider 分派失败；改用正式协议类型并加入编译期断言与无凭据分派测试。另修复能力连接查询漏读 secret_id，导致已保存凭据未传入来源的问题；只携带凭据引用并保留用户过滤，JSON不暴露引用或密钥。仅将已确认属于本地接口契约或缺失凭据引用的微信读书失败任务重新排队，先备份队列与限速行。来源间隔通过进度页各来源设置与管理员 API 校验，存储于来源调度状态表；进度页更新限速说明并区分来源不可读与待重新提取。真实界面审查发现窄屏保存按钮与既有置顶浮钮相叠、俄文标签截断；来源表单预留64px操作边距，窄屏将输入与保存分行，桌面扩大配置列后复查。

影响范围与回滚

booksvr metadata worker、library补全表与事务保护、插件平台配置、元数据进度API及前端显示；spec/元数据.md 与 spec/插件/元数据源.md。表结构仅追加。回滚独立元数据服务ELF和前端，不删除队列；导入主进程与阅读器保持运行。
