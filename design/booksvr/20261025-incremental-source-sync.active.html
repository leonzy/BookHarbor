增量导入与来源同步

BookHarbor 后台空闲开销、稳定挂载身份与安全镜像交接

2026-10-25booksvr / DockerACTIVE来源：用户部署请求

原始诉求

自动扫描改为增量，避免反复全库核对；设备号变化不应误判来源更换，继续保留挂载掉线保护；保留正在执行的导入，测试通过后部署新镜像并统一容器名 bookharbor，提交并推送。

目标与边界

首次受保护或遍历不完整时保留已发现父目录监听，等待变更或有间隔的恢复核对，不因扫描结果异常而每 30 秒重读全库；健康转换只比较轻量检查的结果。后台空闲仅检查根目录身份与健康标记，不遍历书籍或加载全库。启动、人工全量扫描、事件丢失与监控恢复允许完整建立基线。文件事件按路径及子树使用索引查询。保留账号、配置、书库、任务检查点与原挂载；不重置数据库，不复制或删除来源。

设计决策与方案

  1. 来源监控共享事件给自动导入，单写者队列合并事件；自动导入首轮完整发现，此后只扫描变更文件与子目录，运行期间的新事件保留到下一批。已成功入库的路径收到修改或恢复事件时交给来源同步处理，不能重置扫描记录再创建新书；失败或跳过文件仅在 stat 改变时重试。
  2. 来源物理路径建立独立投影与索引，压缩包成员映射到物理压缩包；数据库触发器记录新增及路径变更，仅增量刷新投影。格式登记时在同一事务记录物理来源 stat 基线（ZIP 使用外层压缩包），避免刚导入就改名时缺少移动识别依据；文件 stat 在事务前完成，不读取正文。兼容既有未启用外键的连接，格式删除触发器同时清理 stat 与路径投影，登记复用格式 ID 时替换旧 stat。分批到达的移动事件通过文件身份索引与缺失大小索引查找历史来源；未登记物理文件仅保存路径和大小索引，使跨文件系统先复制后删除也可按大小找候选，再核对内容。首次基线填充，之后仅更新事件子树，关闭自动导入仍生效；不保留正文副本，不回退为周期全库查询。候选文件删除或改动时通过其旧大小索引重新检查相同大小的缺失来源，歧义解除后无需等待完整扫描。路径投影和候选写入使用每 500 条短事务及预编译语句，先取得写锁再读取更新队列，避免活动导入导致读事务升级失败。来源同步无变化时先检查根健康并直接返回；事件同步仅查询受影响子树。
  3. 只读根目录的增量快照没有文件时，从索引有界探测仍可读取的物理文件，不能把局部空快照当成整根目录为空；无法证实非空仍暂停缺失判定。挂载身份优先通过 Linux FS_IOC_GETFSUUID 读取文件系统 UUID、配合根 inode 与覆盖/嵌套挂载拓扑，排除易变设备号和设备名。正式盘实测 F2FS 的 statfs.f_fsid 等于 st_dev（2096），并非稳定 UUID；不能作为 F2FS 的降级身份。使用只读目录 fd 查询 UUID，实测与 findmnt 返回的卷 UUID 一致（原始值仅保存在服务器部署记录中）；无法稳定识别时保持保护。协议依据：Linux UAPI 与 VFS ioctl 实现。旧 v2 身份不能仅凭标记自动信任，部署时核对真实挂载后显式重建基线。恢复或完整重建时重装目录监视，避免监视描述符仍指向掉线后的底层目录。根不可读、健康标记缺失、文件系统或嵌套挂载变化继续阻止缺失判断；提交前再次核对。
  4. 重复跳过记录虽然使用临时唯一哈希，仍为已处理，修正 done 和登记判定，避免反复读取整本 PDF。
  5. 先隔离测试和构建，生产继续导入；切换时通过进程正常退出保存检查点，备份数据库和容器参数，保留回滚容器；恢复自动导入并验证新名称、挂载、任务与空闲开销。

影响范围与风险

涉及 booksvr 来源同步、扫描与后台调度，spec/书库.md、spec/系统设置.md、Compose 默认容器名称与开发镜像地址、部署验证。无界面影响：不改变页面、交互、现有接口字段与前端消费者契约；因此豁免 interface-review。剩余风险为事件丢失、压缩包映射、目录移动与进程交接，需要对应测试。非事件平台使用有明确间隔的恢复核对，不能静默声称立即同步。

测试结果

  • Go 最终全量检查：go test ./... -skip "TestFileThemeStoreWriteFileError|TestBackupCreateFailsOnReadOnlyDir" 与 go vet ./...，全包通过。两个权限用例在非 root 运行验证；另验证只读目录无法读取时不误判缺失。
  • 增量回归：10,000 条无关格式记录只核对 1 条目标；物理路径索引、主键与候选大小索引的 EXPLAIN 查询计划通过；移除测试书籍表后，空闲和受保护目录检查仍成功，证明不读取全库。
  • 来源回归：普通文件与目录改名、移动、删除、恢复，ZIP 物理路径、刚入库即改名、分批复制后删除、候选歧义解除后恢复、只读根目录局部空快照、真正空目录保护、无外键时格式 ID 复用与删除清理，全部通过。
  • 设备识别：模拟设备号与 statfs 设备标识 2080→2096，UUID 不变时身份不变；UUID 替换、嵌套挂载变化及缺失标记继续保护。以 UID 1000、只读挂载在 leonFN 的实际 F2FS 上运行 TestSourceFilesystemUUIDOnRealMount，返回 UUID 与宿主机查询一致。
  • Docker 真实后端验收：安装、登录、初始扫描、内容重复跳过、新文件增量入库、改名与目录移动保留原书号、健康标记失效保护、恢复后确认缺失与源恢复、关闭自动导入后复制再删除的移动，均通过；恢复未重复建书。跨过空闲健康检查周期，源核对为 0，自动扫描时间不再变化；内置书库没有正文 TXT 副本。
  • 镜像管理脚本：python3 -m pytest tests -q -p no:cacheprovider，101 passed；正式及开发 Compose 配置分别解析为 bookharbor / bookharbor-dev，镜像地址正确；规格、方案与差异校验通过。

测试中修正了三个验收夹具问题：自动生成 stat 后原回收站夹具重复插入却忽略错误，改为显式 upsert 并检查错误，保留快照恢复及 ID 重映射断言；随机安装密码改用既有长度范围；临时候选镜像同时更新系统入口与应用载荷入口，并核验运行代码，生产 Dockerfile 本就更新两处。未放宽认证或恢复校验。

无界面影响：未修改 app 文件；调试用 source_sync 模式没有前端枚举消费者，其余字段契约保持。豁免 interface-review；真实后端与现有权限、OPDS、回收站及导入回归提供替代验证。NAS 只验证现有 Linux 本地文件系统，未把未实测的远程文件系统通知可靠性写成通过。
