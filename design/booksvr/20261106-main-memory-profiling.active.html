主服务内存采样与分配路径优化

创建日期：2026-11-06 · 模块：booksvr · 状态：ACTIVE · 需求来源：定位主服务内存占用原因，优化实际分配，保护导入、元数据补全和同书核查，测试部署并提交推送。

原始诉求

容器总计费约 2.5GiB，文件缓存约 1.77GiB，主服务匿名常驻约 536MiB、历史峰值约 1.5GiB；主服务未设置 Go 内存软限制，补全独立进程仅约 40MiB。不能仅靠限制或重启掩盖问题。

目标和决策

  • 先保存实际进程、任务检查点与内存时间序列；区分匿名驻留、文件缓存、存活对象、分配峰值和 SQLite 连接/临时查询开销，不把虚拟地址空间视为实际内存。
  • 在隔离的真实数据库快照或有代表性的大库上复现并采集 Go profile，按证据改为有界分批、数据库筛选、连接复用或释放无用缓存。不给生产进程发送强制 GC、调试中止信号，不对系统 drop_caches。
  • 变更不清空导入或核查队列，不改变元数据保护和合并规则；不重启独立运行的补全、阅读和插件进程。部署前核对导入状态，必要时在现有批次检查点完成后只热更新主服务，确保任务自动续跑。
  • 以相同数据和操作对比优化前后分配量、峰值和驻留；补回归测试、幂等和续跑验证，最终写回实测而非理论值。

影响范围

影响 booksvr 来源核对读取/准备、后台进程装配与私有诊断；document/memory-diagnostics.md 记录运维配置，spec/书库.md 仅更新实现对照的代码落点。用户 API 结果、权限、界面、元数据保护与合并规则不变。无界面影响的判断和豁免见后文。

验证计划（实施前记录）

原定验证项：连续驻留与任务采样、隔离 heap/alloc profile、同数据前后对比、相关 Go 测试和 vet、生产任务检查点及独立 PID 保护、部署后持续采样、设计与 spec 门禁、提交推送。

采样结论与实施细化

生产 smaps 确认主要驻留在 c000... 的 Go 堆映射，不是 SQLite 的外部 mmap。隔离容器以只读挂载查询 498113 条真实来源记录、489482 个物理路径；累计 loader 分配 1156489672 字节、准备缓存分配 211593480 字节，强制 GC 后仍存活 419608976 字节。pprof 的 alloc_space 主要为切片扩容/记录保存 482MiB、SQLite 字符串 319MiB、重复路径缓存 206MiB、filepath.Rel 93MiB、来源引用解码等。采样只运行原准备步骤，没有修改生产数据库或扫描原文件。

按证据优化：完整读取预分配记录切片并省掉无用的全库去重集合；绝对规范路径使用等价前缀判断，避免每条 filepath.Rel 分配；路径存在与先前存在状态用一份小标志表保存；只在缓存复用或显式移动事件实际需要时保存缓存；移动候选索引只建立在缺失来源需要的身份/大小上，仍保留全部同键候选以维持歧义保护。暂不更改 ISBN/元数据/挂载保护规则，也不依靠 GOMEMLIMIT 或周期强制 GC。

定量复测与在线采样

同一只读数据集、相同 CPU 和容器内存条件：记录数保持 498113，物理路径数保持 489482。累计分配从 1368083152 降至 651113248 字节（约减少 52.4%），存活堆从 419608976 降至 310494288 字节。该比较仅覆盖读取与准备阶段，不能冒充整个进程的最终驻留。继续部署前增加默认关闭的本地诊断：只在显式配置私有绝对目录时写运行时内存/连接池 JSON 和有界 heap profile，目录 0700、文件 0600，不开放任何 HTTP 诊断接口、不强制 GC、不改 Go 内存上限；用于验证现网稳定驻留与堆对象。此运维开关不是产品设置，不改变领域行为，使用范围与输出写入运维说明。新代码属于纯后端资源与私有运维诊断，无界面影响，依据为用户 API、文案、权限与前端代码均未改动；interface-review 豁免，剩余风险为大库查询和长时间后台复核的内存波动，需要现场复测。

在线采样推动的第二轮方案

完整来源核对超过十分钟，临时记录在 HTTP 主进程内仍存活，驻留可继续增长到约 1GiB，不能把准备阶段的 52% 改善当作最终稳态。在线 heap 已直接证实 loadSourceTracked 与 WalkDir 快照占绝大部分。采用短生命周期子进程隔离完整核对：以当前同版本可执行文件运行私有 source-sync-worker 命令，JSON stdin 传递已配置路径；目录遍历事件逐条通过 JSON stdout 交给主进程实时装入 inotify，结果只传计数、健康状态和目录列表，不传全文件清单。主进程持有的临时数据限于目录与有界协议消息，完整临时堆随子进程退出由操作系统释放，不依赖 GC 或限制。

子进程只打开已有数据库、注册 Calibre SQL 函数，不跑迁移，不启动导入/补全/合并；沿用完全相同的 SyncSourceFiles 健康复核和原子提交逻辑。增量核对仍在主进程。父上下文取消时结束子进程，未提交 SQLite 事务回滚，已有来源变更日志下次继续应用。失败由原有 source-worker 重试，不以内联重试重新拖大主堆。新增真实子进程协议、目录监听即时传递、取消不误标缺失、结果一致与字段校验测试。此轮等待当前完整核对进入安全边界后更新，保护其他独立进程不变。

子进程协议的保护细化

目录事件采用双向确认：子进程写出目录事件后，必须收到主进程安装监听完成的 continue 确认，才遍历目录内容。不能仅异步写入管道，否则可能在监听尚未安装时漏掉文件变化。测试在目录回调中延迟并创建新子目录，验证它被完整扫描；取消测试将真实工作子进程阻塞在目录事件处，取消父上下文后，书目缺失状态保持上次提交值。还覆盖含逗号根目录、结果一致、移动、无迁移、禁止创建缺失数据库、协议失败与有界 stderr。

复查中补齐省略返回文件清单与旧受限发现模式的兼容：必要的后备发现内部列表仍保留，只不返回给状态消费者，新增有限发现时改名仍能匹配的测试。完整工作请求不传无用的逐文件变更列表。工作连接保持原有 30 秒 SQLite 等待策略，读取与目录监听的主服务行为不变；Windows 现有库 URI 补齐盘符前缀，与只读 CLI 的既有处理一致。领域规格只更新书库的代码落点，未更改同步、权限与任务规则。
