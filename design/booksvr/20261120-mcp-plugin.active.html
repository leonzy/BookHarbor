内置 MCP 插件

让 Agent 通过受权限约束的 MCP 工具查书、获取阅读记录、推荐书籍，并在明确确认后推送或导入书籍。

状态：ACTIVE创建日期：2026-11-20所属模块：booksvr影响范围：插件、HTTP、CLI、文档需求来源：用户原话

1. 原始诉求

“我想给这个项目增加mcp功能，可以从agent里面查找书，推送书，根据要求推荐书，获取阅读记录等。”“mcp能做成一个插件吗？”“做吧，做完自己测试！”

本功能使用内置插件生命周期和连接授权，不引入独立后端，也不修改现有书库权限模型。

2. 目标与非目标

  • 提供 book_search、reading_history、book_recommend、book_send、book_import、task_status。
  • 支持 Streamable HTTP 的 JSON-RPC 生命周期和本机 stdio 子命令，共用同一实现。
  • 复用私藏书、目录 ACL、读者权限、书源连接、推送连接和后台进度。
  • 默认拒绝远程访问和写入；写操作必须预检、执行并带幂等键。

非目标：不开放任意路径、URL、SQL、Shell 或 Calibre 参数；不制作通用 execute() 后门；不提供 LLM 服务；不新增前端页面；不跨进程恢复临时任务。

3. 方案

插件契约
talebook.combo.mcp
声明 integrations.mcp 与类型化 MCPProvider。
身份与授权
HTTP 本地 Cookie 或连接 Bearer；stdio 显式用户。逐请求检查启停、连接所有者与 scope。
只读工具
搜索、当前用户阅读记录、可解释推荐，统一在元数据返回前过滤不可见资源。
受控写入
预检生成短期操作；execute 使用幂等键；推送和书源导入进入进程内任务。

协议与数据

实现 initialize、notifications/initialized、ping、tools/list、tools/call。工具结果使用 MCP content 和 structuredContent，不套旧 API 的 err:ok 信封。请求体有界，参数有白名单和数量上限。

写入边界

推送通过现有 PushProvider 和 sourcefile.Acquire；导入通过现有 saveOnlineService 的安全书源目录路径，由 HTTP 装配回调注入核心包，避免包循环。任务不返回物理路径、密文或原始异常。

6. 决策记录

  • 插件身份固定为 talebook.combo.mcp，能力固定为 integrations.mcp。
  • MCP 编译进现有 booksvr 二进制并运行在同一容器和进程；不新增 Compose 服务、镜像或监听端口。测试用 golang 容器只承担隔离编译，不属于交付部署。
  • 不新增 mcp_tasks 表；临时操作与任务进程内保存，重启后不可查询。
  • 远程与写入分别由连接的 allow_remote、allow_write 开启，读取默认不放开公网。
  • stdio 必须显式指定 --user-id，不隐式使用管理员身份。
