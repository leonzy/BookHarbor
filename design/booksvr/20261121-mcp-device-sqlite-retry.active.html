MCP 设备事务锁冲突重试

创建日期：2026-11-21 · 所属模块：booksvr

需求来源：真实 MCP 设备新增、修改、删除验收。

1. 原始诉求

设备管理和按设备推送已在 design/booksvr/20261120-mcp-devices.active.html 生效。真实 HTTP 验收中，设备事务与插件审计写入竞争，异步任务偶发 SQLITE_BUSY，需保证正常重试成功且不绕过确认。

2. 目标与影响范围

仅修改 MCP 设备事务和对应测试。锁冲突时以新事务重新读取设备、验证预检快照并有限重试；非锁错误不重试，其他写入工具行为不变。异步内部错误写入日志，Agent 仍只收到脱敏结果。影响 spec/插件/MCP.md 的可靠性说明。

3. 方案

将单次设备事务封装为内部步骤，最多进行五次短间隔重试。每次重试重新开启事务，因此不会复用已经被审计写入推进的 SQLite 快照。外部幂等键和任务归属保持不变。

4. 测试结果

  • 另一连接的写事务持锁时，设备更新在释放后成功，设备内容正确。
  • go test ./internal/mcp 与 go vet ./internal/mcp 通过。
  • 真实 HTTP 验收先复现 SQLITE_BUSY；修复后新增、列出、修改、删除、任务状态和重复执行幂等全部通过，临时设备与实例已清理。
  • 真实 HTTP/stdio 的初始化、工具发现、查书、阅读记录、设备列表和默认只读均通过；新版个人令牌 Playwright 通过。

全量 go test -timeout=20m ./... 与 go vet ./... 通过，包括 httpapi、mcp 和既有 library 包。2026-11-21 已随主镜像部署到 leonFN 的现有 bookharbor 容器；健康、挂载、端口、设备映射、默认认证和回滚备份检查通过，没有新增 MCP 服务或容器。
