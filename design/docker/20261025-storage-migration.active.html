BookHarbor 存储迁移

2026-10-25 · docker · ACTIVE · 来源：用户授权执行迁移与旧 Talebook 清理

原始诉求与目标

系统分区只承担系统用途；本次不缩小 sdc2。BookHarbor 源码、运行数据、缓存、备份、归档和发布包迁入 sdc3。最终使用飞牛管理的原生卷路径。sdb 不放这些资料，sdd 书籍原文件与 Docker 根目录保持原位置。

方案与目录

飞牛创建存储空间 2：ext4 / Basic，sdc3 → md1 → LVM → /vol2。分区约 190.47 GiB，界面文件系统总容量约 188.25 GB。UUID：761c3410-e878-44c7-b0c4-8b392bc87888。sdc1、sdc2 起始位置和大小不变。

切换与启动保护

预复制后停止服务、最终同步、全量文件 checksum 比较、两套 SQLite quick_check 与记录数比较。新容器保留原镜像、环境、端口和书籍挂载，仅替换 /data 路径。旧容器和数据保留到验证完成。

bookharbor.service 启动前检查数据卷和书籍卷 UUID 及数据库文件，失败后重试。maintenance/env.sh 设置构建缓存和临时目录。backup.py 通过 SQLite backup API 生成快照并重新打开验证。

影响范围：宿主机存储、部署及运维路径，不改变产品行为，无 spec 修改。无界面影响，豁免 interface-review 和产品代码测试，以实际部署验收代替。未安排整机重启，以免影响其他容器。

实施调整与回退

最初手工 /mnt/data 方案遗漏飞牛管理集成。用户纠正后停止复制、保留生产数据、暂存新增归档、撤销手工挂载及 fstab 条目。经最终格式化确认后改由飞牛建立 /vol2。

保存分区表、fstab、容器配置和原 sdc3 的 8,481,931,264 字节压缩镜像，gzip 与原始 SHA256 校验通过。原始 SHA256：12da919025eeed10c00142654fc21a000ff8f46a1fbc86329e16cf17a63ad91f。切换异常自动恢复旧容器；旧目录清理后依赖新卷备份与源码归档恢复。卷内备份用于操作回退，不提供整盘损坏保护。

迁移前后数据库 quick_check 均为 ok，书籍数 380,783、用户数 1 一致。真实登录、书库及目录 API、扫描与监听状态、抽样书籍详情和搜索、封面、阅读页面、OPDS 全部通过。unshare 私有挂载命名空间内卸载 /vol2 后启动保护拒绝执行，宿主机挂载不受影响。普通用户加载 env.sh 并创建、删除构建临时文件通过。两份备份快照重新打开后 quick_check 均通过，记录数为 380,783 和 1。首次服务重启发现 Nginx 日志权限 000 导致启动自检失败，已恢复迁移数据所有者的读写及目录遍历权限，并通过 nginx -t；修复后再次重启，真实登录、书库、封面、阅读与 OPDS 全部通过；验证记录时间晚于容器重启时间。Supervisor 停止旧进程时曾在等待后使用 SIGKILL，属于本镜像关闭行为，不能将本次服务重启等同于整机断电恢复验证。旧容器、旧源码、旧运行目录、旧维护目录、旧构建缓存及 sda 临时中转资料均已清理，act 缓存入口改为指向新卷的符号链接。清理后服务 active/enabled，欢迎接口正常，容器 /data 指向新卷。最终 df -h：系统分区约用 18G、可用 28G；/vol1 约用 33G、可用 84G；/vol2 约用 37G、可用 152G。sdc2 大小保持 51,439,992,832 字节。
