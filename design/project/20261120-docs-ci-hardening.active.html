现行文档与 CI 完整性治理

把现行文档统一到 Go 后端与 BookHarbor 发布边界，并让 CI 覆盖完整单测、静态检查、依赖风险和真实容器启动。

状态：ACTIVE 创建日期：2026-11-20 所属模块：project 影响范围：根目录文档、document、app、booksvr/docs、.github/workflows、Dependabot 需求来源：用户要求“把文档全部更新一下，过时的改掉或者删除。ci也给我完善了”

1. 原始诉求

“把文档全部更新一下，过时的改掉或者删除。ci也给我完善了”

现行文档仍包含旧 Python/Tornado 后端、 Talebook 发布地址和默认 Nuxt 模板内容；CI 只执行部分前端单测，缺少 Python lint、依赖风险与真实容器业务入口验证。

2. 目标与边界

  • 现行安装、使用、开发、插件、安全和架构文档必须描述当前 Go + Nuxt 实现及 BookHarbor 仓库。
  • 带固定提交、PR 或验收日期的材料明确标记为历史记录；不改写其历史结论。
  • CI 运行全部适用 Vitest 单测、现有浏览器回归、Go/Python 检查、依赖审查和本地镜像冒烟。
  • 不改变产品 API、数据库、页面交互和部署数据目录，不处理用户已有无关改动。

4. 方案

文档所有权：README 提供入口，document 提供使用与开发说明，CODE_WIKI 提供代码导航，spec 继续作为领域规则唯一来源，design/research 和带固定证据的评审记录保留时态。
  1. 重写已失效的现行文档，删除没有引用且与 README 重复的旧功能清单。
  2. 对历史盘点和评审文档增加醒目的历史边界，当前路由和架构指向 Go 实现。
  3. CI 增加权限、超时和并发取消，集中执行全量单测与 Python lint。
  4. 新增 Go 漏洞检查和 PR 依赖审查，扩展 Dependabot 到 npm、Go、Python、Docker 与 Actions。
  5. 构建 workflow 在不会发布的 amd64 本地镜像上运行容器，失败输出日志并始终清理。

5. 影响范围、风险与回滚

产品行为：不改变产品行为，因此无需修改 spec/ 篇目。现有用户无关的 spec 改动保持原样。

风险：全量单测或新增安全检查可能暴露已有问题；容器冒烟依赖镜像启动时序。CI 必须如实失败并输出日志，不能通过跳过或放宽断言制造绿色结果。

回滚：文档和 workflow 均按文件回滚，无数据库或数据目录迁移。新增的依赖 PR 只影响后续更新，不直接修改生产依赖。

7. 决策记录

  1. 2026-11-20：历史评审和路由盘点保留，但增加历史定位；现行指南必须无旧后端操作指令。
  2. 2026-11-20：真实容器冒烟放入现有构建 workflow，避免在 CI workflow 重复完整镜像构建。
  3. 2026-11-20：i18n 的 JSON 与编译敏感字符作为阻断门禁；动态 key、未静态引用 key 和回退翻译仅报告，避免把合法动态用法误判为失败。
  4. 2026-11-20：leonFN 的真实 test-server 首次运行发现 Go 1.22 无法编译 `t.Context()`；为保持项目 Go 1.22 基线，将该测试改为 `context.Background()` 并重新执行完整 job。
  5. 2026-11-20：leonFN 首次 test-ui 在新增 npm 生产依赖审计发现 57 项公告，尚未进入 lint/单测；第一轮非 force `npm audit fix` 将公告降至 15 项，剩余项仍可修复，继续用缓存执行第二轮收敛，不采用强制降级。
  6. 2026-11-20：Go 漏洞扫描确认 71 项可达问题，其中 Go 1.22 标准库占主要部分；最新安全依赖要求 Go 1.26，因此构建与 CI 直接升级到 Go 1.26 并更新 `golang.org/x/*`，再重跑全量测试。此前的 1.22 测试兼容修复保留。
  7. 2026-11-20：setup-go 不再从会被 tidy 写成精确补丁的 `go 1.26.0` 推导版本；两个 Go job 使用 `go-version: 1.26` 与 `check-latest: true`，确保采用最新安全补丁。
  8. 2026-11-20：npm 通用修复未收敛后，显式升级 Nuxt 4.6.4、@nuxtjs/i18n 10.6.0；测试栈使用支持 Vitest 5 的 @nuxt/test-utils 4.4.0，并升级 Vitest 5.1.1 与 Happy DOM 21.0.4，避免强制内部覆盖。
  9. 2026-11-20：Vitest 82 个 suite 的共同 `moduleType` 收集错误来自根 Vite 7 与 Nuxt/Vitest Vite 8 混用；显式对齐根 Vite 8.3.8 后样本 suite 25/25 通过。新版 i18n 模块的 vueI18n 相对路径改为 `../i18n.config.ts`，并添加 Nuxt 配置回归测试。
  10. 2026-11-20：全量 Vitest 暴露的旧 Python 路径测试已改到 Go/resources；Go 插件使用的 11 个 MDI 名称已登记或映射。Nuxt 组件测试保留真实 Nuxt app 并注入后端 mock，避免初始化被全局 useNuxtApp mock 破坏；补齐 74 个俄文文案及插值。
  11. 2026-11-20：本地 act 验证使用 Ubuntu 24.04 runner 匹配真实浏览器 job，并修正临时 Chromium 缓存执行权限。Windows 工作区 CRLF 启动脚本只在远程验证副本转 LF；Git 属性及 GitHub Linux checkout 本就会产生 LF，不把该环境差异改成产品补丁。
  12. 2026-11-20：一次完整 CI 中 Upload 的 Nuxt 初始化超过默认 10 秒，单独复验通过 10/10；将 Vitest hookTimeout 提高到 30 秒，避免资源负载下把初始化超时误判为业务失败，然后再次运行完整聚合。
