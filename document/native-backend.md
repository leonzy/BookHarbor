# Go 原生后端

本分支由 `booksvr` 提供全部应用 HTTP 接口，Nginx 提供前端静态页面。旧的 Python HTTP 服务、ORM 模型和对应应用测试已删除。Calibre 的格式处理工具、镜像启动自检、签名升级执行器和离线工程校验仍使用 Python，不需要启动 Tornado。

## 构建和测试

```sh
cd booksvr
go test ./...
go vet ./...
go build ./cmd/booksvr
```

前端在 `app/` 中构建。容器可使用 `Dockerfile` 的 `production` 或 `production-spa` 目标；`test` 目标以普通用户运行 Go 测试，避免 root 绕过权限测试。镜像管理脚本的测试使用 `python3 -m pytest tests`。

## 数据与启动

- Calibre 元数据继续保存在 `/data/books/library/metadata.db` 。
- 账号、站点数据和导入记录继续保存在 `/data/books/calibre-webserver.db` 。
- 配置继续使用 `/data/books/settings/auto.py` 和 `manual.py` ，按数据解析，不执行配置代码；手工配置覆盖自动配置。
- 容器自检通过 `booksvr bootstrap` 初始化用户表、补充缺失字段并生成首次安装密钥。已有账号和设置不会被重置；已有书库不需要迁移。
- 原始书籍目录可以分别挂载到 `/books` 、`/books1` 等路径；默认只索引文件，不复制书籍。
- 图片、阅读模板和内置书源数据位于 `resources/` ，不再放在 Python 服务目录中。

## 推荐与导入控制

首页推荐按读者兴趣匹配作者、标签和系列；没有兴趣记录时优先展示热门书籍。已在读、已读、不可见和来源缺失的书籍不会进入推荐结果。候选元数据有数量上限，完整书卡只读取最终结果。新书按入库时间排列。

管理员可通过“停止当前任务”停止扫描和导入。已完成结果保留，剩余记录仍可处理；暂停状态跨容器重启保存，自动导入不会立即重新启动。再次扫描或导入会解除暂停。目录删除、移动和改名同步仍独立运行，并保留挂载掉线保护。

容器正常退出造成的全量导入中断继续使用持久断点恢复；用户主动停止的任务不会被当作异常中断恢复。

## 应用升级包

原生升级包包含 `booksvr` 二进制、静态前端和资源文件。签名、运行环境及数据库指纹检查继续生效；旧 Python 升级包不能替换原生后端。镜像管理脚本始终由镜像提供，不能被应用升级包替换。
