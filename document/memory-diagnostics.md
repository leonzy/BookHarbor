# 主服务内存诊断

默认不采样。需要排查时，仅给主服务进程设置 `BOOKSVR_MEMORY_PROFILE_DIR` 为前端静态目录之外的私有绝对目录，例如 `/data/diagnostics/main-memory`。

目录权限为 0700，文件权限为 0600。每次启动后的十分钟内，每 30 秒原子替换 `memory.json`，记录 Go 堆、回收与数据库连接池统计；每两分钟替换 `heap.pprof`，十分钟后自动停止采样。只保留当前两个文件，不创建 HTTP 调试端口，不强制 GC，不修改内存上限，不读取或重置后台任务状态。文件可能包含内部路径和内存中的业务数据，应只供本机运维读取，不放入共享目录或公开附件。

用与运行版本对应的二进制执行 `go tool pprof -top -inuse_space booksvr heap.pprof` 查看存活对象；`-alloc_space` 查看累计分配。累计分配不是当前内存占用，文件缓存也不能当作 Go 堆。结合 `memory.json`、进程 RSS 与 cgroup 的 `anon` / `file` 时间序列判断。

隔离复现可运行 `TestMemoryProbeSourceBaseline`，显式提供 `BOOKHARBOR_MEMORY_PROBE_DB` 和 `BOOKHARBOR_MEMORY_PROBE_PROFILE`。数据库必须只读挂载；该用例不扫描源文件、不写生产库，普通测试默认跳过。该阶段测量只覆盖来源记录读取和核对准备，不能代替整个服务的现场采样。

## 完整来源核对的临时进程

完整来源核对由同版本 `booksvr source-sync-worker` 子进程执行，主服务不持有全库临时快照。目录遍历事件实时传回主进程以安装文件监听；计数与健康状态在核对完成后返回。子进程只打开现有书库，不做数据库迁移，也不启动导入、补全或合并任务。增量来源核对继续在主服务内执行。

临时进程完成即退出，其堆由操作系统释放。Linux 有 `nice` 时降低它的 CPU 优先级，并使用单个 Go 调度处理器；未增加内存上限。取消时结束临时进程，SQLite 未提交事务回滚，沿用原有健康检查与重试规则。核对期间容器的总内存仍会包含临时进程和可回收文件缓存，不能只看主进程或把短期峰值当成常驻泄漏。
